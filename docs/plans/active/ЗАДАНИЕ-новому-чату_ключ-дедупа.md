## Задача

**Ключ дедупа склеивает разные товары, и они не попадают в поиск цен.**

Ключ сегодня: `(первые 60 символов полного имени, product_code, manufacturer)` —
`specClassifier.ts` (функция `classifySpecPositions`) и `zamer_sloj_marka.py` (`load_layer_c`),
плюс `zapis_v_sistemu.py` (`load_positions`). Полное имя собирается склейкой с родителями,
поэтому у длинных родительских названий различающий кусок уходит за 60-й символ.

**Замер, уже сделанный (не переделывать, проверить и расширить):**

| проект | строк | истинных повторов | РАЗНЫХ позиций склеено | из них группа C (ушли бы в поиск) |
|---|---|---|---|---|
| 20 (Арта, спец. 34) | 252 | 62 | 10 | **1** |
| 18 | 140 | 21 | 90 | 26 |
| 26 | 736 | 181 | 111 | 28 |
| 30 (19_8-24-ОВ.xlsx) | 704 | 185 | **153** | **61** |

Пример: радиаторы `C11-300-500 / C11-300-600 / C11-300-700 / C11-300-800` — разные товары
с разными ценами — считаются одной позицией.

**Цель:** вернуть в поиск позиции, которые сейчас теряются, не наплодив дублей-запросов
на действительно одинаковых строках.

## Как делать

1. **Сначала замер, потом код.** На всех проектах базы посчитать: сколько позиций вернётся
   в поиск при новом ключе и сколько появится лишних прогонов по настоящим повторам.
   Кандидаты ключа: собственное `name` позиции вместо среза родительской склейки;
   `name` + `unit`; полное имя целиком; добавление `characteristics`.
   Выбирать по замеру, а не по вкусу.
2. **Ключ живёт в ДВУХ местах** — правило в python (по нему идёт поиск) и в TS (по нему экран).
   Менять оба и обязательно прогонять сверку, три команды из README price-harvester.
   Ожидаемое — «РАСХОЖДЕНИЙ НЕТ — 1:1» на 7039 строках.
3. **Проверить, что дороже не стало.** Больше позиций в слое = длиннее прогон и больше
   расход квоты Yandex Search. Посчитать в позициях и в минутах на спецификации Арты.
4. **Пять ходов перед выкладкой** — по `.claude/skills/pre-deploy-check/SKILL.md`, отдельными
   свежими проверяющими. Критерий остановки записать вслух ДО первого хода.

## Грабли этого участка

- `npx tsc --noEmit` во фронте этого репо **не проверяет ничего** (корневой tsconfig —
  solution-файл). Проверять `npm run build`.
- После правки SQL внутри шаблонной строки — выполнить запрос, сборка его не видит.
- Кириллица в `.bat` ломает cmd: внутри только ASCII.
- Пересборка спецификации (`reparse`) пересоздаёт позиции — старые цены становятся сиротами.
- Прод-API закрыт `API_SECRET`; секрет в `price-harvester/secrets/prod_api.txt`,
  вход для людей — ссылка `?k=<секрет>`.
- Деплой ручной: `gh workflow run deploy.yml --ref main` после пуша.

## Что НЕ делать

- Не менять правило только в TS «чтобы экран стал красивее» — поиск пойдёт по старому.
- Не расширять ключ до уникальности по `id`: тогда одинаковые строки спецификации дадут
  повторные запросы и лишний расход квоты.
- Не коммитить через `git add -A` — в дереве чужие незакоммиченные правки.
