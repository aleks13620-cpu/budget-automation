Дата: 26.08.2026. Проект budget-automation (Арта, снабженец Иван).
Вариант A: кнопка кладёт задание в таблицу; поиск выполняет скрипт на РАБОЧЕЙ машине
(там ключ Yandex Search и «домашний» IP), результат возвращается в прод через API.

Три исполнителя работают по этому файлу и НЕ трогают чужие файлы.

## Общее

- Авторизация: весь `/api` уже закрыт `API_SECRET` (заголовок `Authorization: Bearer <secret>`).
  Ничего нового не изобретать.
- Даты — ISO-строки UTC (`new Date().toISOString()` / `datetime.now(timezone.utc).isoformat()`).
- Область поиска — ПРОЕКТ целиком (`specification_items.project_id`), как у выгрузки Excel,
  а не одна спецификация.

## Таблица очереди (миграция в backend/src/database/init.ts, в общий массив migrations)

```sql
CREATE TABLE IF NOT EXISTS price_search_jobs (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  project_id   INTEGER NOT NULL,
  status       TEXT NOT NULL DEFAULT 'queued',   -- queued | running | done | error
  requested_at TEXT NOT NULL,
  started_at   TEXT,
  finished_at  TEXT,
  rows_written INTEGER,
  message      TEXT
);
CREATE INDEX IF NOT EXISTS idx_price_search_jobs_status ON price_search_jobs(status);
```

## Эндпоинты (новый файл backend/src/routes/priceSearch.ts, смонтировать в index.ts)

### 1. POST /api/projects/:id/price-search — кнопка
- нет проекта → 404 `{error}`
- у проекта уже есть job в `queued|running` → 409 `{error, jobId, status}`
- у проекта нет ни одной позиции спецификации → 400 `{error:'В проекте нет позиций спецификации'}`
- иначе INSERT (`status='queued'`, `requested_at=now`) → 200 `{jobId, status:'queued', items:<число позиций>}`

### 2. GET /api/projects/:id/price-search/status — опрос из браузера
Последняя job проекта (`ORDER BY id DESC LIMIT 1`).
- нет ни одной → `{status:'idle'}`
- иначе `{jobId, status, requestedAt, startedAt, finishedAt, rowsWritten, message}`

### 3. GET /api/price-search/jobs/next — воркер забирает работу
Атомарно (одна better-sqlite3 транзакция): взять самую старую `queued`,
перевести в `running`, проставить `started_at`.
- нет заданий → 200 `{job:null}`
- иначе 200 `{job:{id, projectId}, items:[...]}`, где items — `SELECT * FROM specification_items
  WHERE project_id = ?` (ВСЕ колонки как есть, массив объектов; ключи = имена колонок).
  Воркеру нужны id, project_id, parent_item_id, full_name, name, product_code, manufacturer,
  unit, quantity, characteristics — поэтому именно `SELECT *`, а не список полей.

### 4. POST /api/price-search/jobs/:id/result — воркер отдаёт результат
Тело: `{snapshotDate:'YYYY-MM-DD', rows:[ ... ]}`, где каждая строка — ровно поля UPSERT
таблицы `external_prices` (см. price-harvester/src/db.py: business_key, project_id,
spec_item_id, query_name, source, source_url, snapshot_date, supplier_name, manufacturer,
article, name, unit, price, currency, vat_included, vat_rate, min_batch, lead_time_days,
in_stock, match_score, status, raw_data, created_at, updated_at).

Порядок (одна транзакция):
1. job существует и в статусе `running` → иначе 409.
2. **Предохранитель, громкий:** каждый `spec_item_id` должен существовать в
   `specification_items` с `project_id = job.project_id`. Хоть одна чужая → НИЧЕГО не пишем,
   job → `error` с понятным message, ответ 400 `{error, badIds:[первые 5]}`.
   (Молча обнулять или молча пропускать — запрещено, на этом уже обожглись.)
3. UPSERT строк тем же `ON CONFLICT(business_key) DO UPDATE`, что в price-harvester/src/db.py.
4. job → `done`, `rows_written = rows.length`, `finished_at = now`, message —
   короткая сводка по статусам, например `found=162, not_found=9, blocked=116, skipped=121`.
Ответ 200 `{status:'done', rowsWritten}`.

### 5. POST /api/price-search/jobs/:id/error — воркер сообщает о падении
Тело `{message}` → job → `error`, `finished_at=now`, message обрезать до 500 символов. 200 `{status:'error'}`.

## Фронт (frontend/src/pages/MatchingView.tsx)

Кнопка «Найти цены в интернете» рядом с кнопкой выгрузки — там, где Иван уже работает.
- нажатие → POST 1 → опрос 2 раз в 10 секунд, пока `queued|running`;
- на маунте страницы — один запрос статуса, чтобы вернувшийся Иван видел, что прогон идёт;
- тексты для Ивана, на «ВЫ», без техжаргона:
  - queued: «Заявка принята. Поиск начнётся в течение нескольких минут — страницу можно закрыть.»
  - running: «Идём по позициям, ищем цены. Обычно 15–30 минут. Страницу можно закрыть.»
  - done: «Готово: цены записаны (строк: N). Откройте выгрузку — колонки «Цена из интернета», «Продавец», «Группа», «Найдено по».»
  - error: «Поиск не завершился: <message>. Мы уже видим это и разберёмся.»
- 409 → показать, что поиск по этому проекту уже идёт.

## Воркер (price-harvester/worker.py, рабочая машина)

Env: `BUDGET_API_URL` (например `https://<прод>/api`), `BUDGET_API_SECRET`.
Цикл раз в 60 секунд:
1. GET `/price-search/jobs/next`; нет работы → спать.
2. Сложить полученные позиции во ВРЕМЕННУЮ sqlite (tempfile): таблица `specification_items`
   со всеми пришедшими колонками (типы не указывать — sqlite динамический), значения как есть,
   но `specification_id = 1` у всех строк. **id позиций сохранять прод-овские** — именно на них
   потом встанут цены (переливка дампом запрещена, id сквозные).
3. Запустить существующие скрипты подпроцессами с env `SPEC_ID=1`, `BUDGET_DB_PATH=<temp.db>`,
   `PYTHONUTF8=1`: сначала `research/zamer_sloj_marka.py`, затем `research/zapis_v_sistemu.py`.
4. Прочитать из temp.db `SELECT * FROM external_prices WHERE source='web_search'` → POST в 4
   (`snapshotDate` — из строк). Временный файл удалить.
5. Любое исключение/ненулевой код возврата → POST в 5 с текстом (хвост stderr), job не зависает.

Режимы: `python worker.py` — цикл; `python worker.py once` — один проход; `python worker.py selfcheck`
— assert-проверка сборки temp-базы и разбора ответа на фейковых данных, БЕЗ сети и без ключей.

Правки в двух скриптах — минимальные, поведение по умолчанию не меняется:
- `zamer_sloj_marka.py`: `SPEC_ID = int(os.environ.get("SPEC_ID", 34))` и путь к базе
  `os.environ.get("BUDGET_DB_PATH", ROOT + "/database/budget_automation.db")` в `load_layer_c`.
- `zapis_v_sistemu.py`: `SPEC_ID = int(os.environ.get("SPEC_ID", 34))` (BUDGET_DB_PATH уже читается common.py).
