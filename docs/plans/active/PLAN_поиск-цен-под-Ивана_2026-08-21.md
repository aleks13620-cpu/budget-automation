# План: поиск цен по спецификации под правило Ивана

**Дата:** 21.08.2026
**Основание:** три замера за 21.08 (по счетам, по спецификации, по спецификации с фиксами)
**Правило приёмки задано Иваном:** «чтобы мы туда почти вообще не лезли».
Позиция, требующая подтверждения, для него бесполезна — «проще поставим цифру сами».

## 1. ДО и ПОСЛЕ — доказано прогоном на одних и тех же 60 позициях

Материал: спецификация `19_8-24-ОВ.xlsx`, 60 позиций, выбраны механически (каждая N-я).

| Показатель | ДО (замер 2) | ПОСЛЕ (замер 3) | Чем доказано |
|---|---|---|---|
| Позиций искали | 60 (все подряд) | **43** | 17 изготавливаемых выведены из поиска |
| Цена найдена | 28 (47%) | **30 (70% от искомых)** | `zamer_spec2_result.csv` |
| Сорвалось по блокировкам 403/429/401 | **20** | **1** | подсчёт по причинам отказа |
| Цены со страниц-витрин | 5 | **0** | правило «только карточка товара» |
| Позиции с кодом: найдено | 16 из 32 (50%) | **20 из 33 (61%)** | код подтверждён на странице |

**Что сработало, конкретно:**

- **Отсев тех, кто не пускает.** Ozon, Wildberries, ВсеИнструменты, Лунда исключены из
  выдачи заранее — они стабильно отдают 403/401. Освободившиеся слоты ушли на магазины,
  которые отвечают. Результат: технические потери **20 → 1**.
- **Только карточка товара.** Страница обязана иметь разметку `schema.org/Product` или
  `og:type=product`; если товаров в разметке больше трёх — это витрина, отвергаем.
  Побочный эффект оказался ценнее ожидаемого: там, где раньше бралась цена «откуда-то со
  страницы», теперь видно **название карточки** — и его можно сверить с позицией.
- **Изготавливаемое не ищется.** Воздуховоды и отводы из оцинковки по ГОСТ 14918-90
  помечаются «расчёт по площади». 17 позиций из 60 (28%) ушли из знаменателя честно.

**Признаю ошибку прошлого разбора.** Вчерашний вывод «пять ложных цен» был неточен: три из
пяти оказались верными — например, «Компенсатор тепловых расширений 1100х500» получил цену
карточки `SHUFT-KLTR-1100_500`, это правильный товар. Я судил по адресу страницы, не увидев
названия карточки. Теперь название видно, и судить можно по нему.

## 2. Что осталось нерешённым — честно

**Позиции без кода изделия — 10 из 43.** Формально найдено 100%, фактически проверка
глазами даёт: 5 верных, 3 неверных, 2 спорных.

| Позиция спецификации | Что подставилось | Оценка |
|---|---|---|
| Комплект трубок Г-образ. Ø16 | Комплект трубок REHAU RAUTITAN | верно |
| Цилиндры теплоизоляционные кашированные фольгой | Цилиндры ROCKWOOL 100 кашированные фольгой | верно |
| Термометр биметалл. Ø80мм **L=100 мм** | Термометр Росма БТ-51.211 **L=80мм** | размер не тот |
| Преобразователь давления **СДВ-И** | Ридан **MBS 1700R** | другая модель |
| Металл сортовой для крепления воздуховодов | Хомуты для воздуховодов | другой товар |

Причина одна: когда у позиции нет кода, сверять нечего — остаются слова и числа, а они
совпадают у похожих, но разных товаров. **Это работа матчинга, а не поиска.**

**Оставшиеся 13 ненайденных распадаются на два вида:**
- 9 — код изделия не найден ни на одной странице. Это клапаны Везы (КЛАД, ПРОК),
  конфигурируемые узлы Ридан (TDU.5R), Питерфлоу. Их **нет в открытой продаже** — второй
  замер подряд подтверждает.
- 4 — есть только витрины без карточек. Потенциал доработки.

**Лунда закрыта капчей.** HTTP 401 + «с вашего IP замечена подозрительная активность».
Личный кабинет не помогает: капча срабатывает до авторизации. Техническая задача не решается.

## 3. План

### Фаза 1. Довести точность до правила Ивана · 6–8 ч

**Что делаем.** Разделяем результат на два потока по признаку доказуемости:

- **Есть код изделия и он подтверждён на карточке** → цена ставится автоматически,
  Иван к ней не прикасается. Сейчас это 20 позиций из 43.
- **Кода нет** → цена **не ставится молча**. Позиция уходит в отдельный список «оценка,
  не подтверждено» с найденным вариантом и ссылкой.

**Зачем именно так.** Это прямой ответ на правило Ивана. Он не проверяет автоматическую
часть — она доказана кодом изделия. Список «оценка» он может игнорировать целиком: там он
работает как сегодня, хуже не стало.

**Плюс:** поиск карточки внутри витрины (вернёт часть из 4 позиций).

**Критерий готовности:** в автоматической части **ноль** позиций без подтверждённого кода.

### Фаза 2. Прогон на расходке целиком и показ Ивану · 6–8 ч

Он просил дословно: «возьмите любой проект, пусть по сайтам поищет, мы посмотрим результат».

**Что делаем.** Весь раздел расходки его проекта (не выборка), результат — файл рядом со
спецификацией: позиция, найденная цена, ссылка, название карточки.

**Критерий готовности — не наш, а его.** Вопрос Ивану ставим так: «сколько строк отсюда
ты бы поставил в смету не глядя». Его ответ и есть метрика.

### Фаза 3. Встроить в систему · 16–20 ч

Инфраструктура уже есть и не требует переделки: таблица `external_prices` с полями
`spec_item_id`, `source_url`, `match_score`; в ней уже лежит 1293 цены от пяти источников.
Добавляем Search API как ещё один источник и запуск по спецификации из интерфейса.

### Фаза 4. Изготавливаемое — расчёт, а не поиск · 12–16 ч

28% спецификации (воздуховоды, отводы, переходы) поиском не берутся никогда. Их считают
по площади металла и толщине — это калькулятор по ГОСТ, отдельная механика. **Пока не
сделано, «полная смета» невозможна ни при каком качестве поиска** — об этом честно
говорить Ивану.

### Фаза 5. Лунда — переговоры, не разработка · 0 ч разработки

Запросить у Лунды выгрузку прайса или обмен по действующему договору Арты. Это разговор
Алексея с Арты и Арты с Лундой. Технического решения нет и не будет.

## 4. Что план даёт и чего не даёт

**Даёт.** По товарной части спецификации (43 позиции из 60) — автоматическое закрытие
примерно половины **с доказанным совпадением по коду**, без риска подсунуть чужую цену.
Плюс список кандидатов по остальному, который можно не смотреть.

**Не даёт.** Спецификацию целиком не закроет никогда: 28% изготавливается, а не покупается;
ещё часть — проектное оборудование без публичных цен. Обещать Ивану «нажал — получил смету»
на этих данных нельзя.

**Формулировка для Ивана, честная:** «расходку по позициям с артикулом посчитает сама и
спрашивать не будет. Воздуховоды и проектное оборудование останутся на запросе счетов,
как сейчас».

## 5. Чем этот план проверяется

Каждая фаза имеет числовой критерий, а не «стало лучше»:

| Фаза | Критерий |
|---|---|
| 1 | ноль позиций без подтверждённого кода в автоматической части |
| 2 | вердикт Ивана: сколько строк поставит в смету не глядя |
| 3 | цены из Search API видны в карточке проекта, `external_prices` пополняется |
| 4 | расчёт воздуховодов сходится с фактическим счётом на ±10% |

# ПРИЛОЖЕНИЕ (21.08.2026, вечер): архитектура из трёх слоёв — проверка

Идея CEO: добавить слой ИИ, который разбирается в характеристиках карточки (как Иван,
когда проваливается в товар); выдавать 3 варианта с ценами; а то, что не нашлось в вебе, —
запрашивать у поставщиков по почте и разбирать ответные счета автоматически.

## Слой 1. ИИ читает характеристики — ПОДТВЕРЖДЁН

Тест: 10 позиций без кода изделия (там, где алгоритм ошибался), две модели независимо,
эталон проставлен вручную.

| Модель | Совпало с эталоном |
|---|---|
| GigaChat-2-Max | 6 из 10 |
| Gemini 2.5 Flash | 6 из 10 |

Профиль ошибок разный, и это важнее цифры. ИИ поймал то, чего код не видит:
«длина погружной части L=80 вместо требуемой L=100», «кг против штук», «нет информации
об оцинковке», «товар архивный, снят с продажи» (последнее — точнее моего эталона).

**Ограничение:** обе модели согласованно сказали «подходит» только по 1 позиции из 10.
ИИ надёжен как ОТСЕИВАТЕЛЬ и ОБЪЯСНИТЕЛЬ, не как утверждатель.

## Слой 1-бис. Hard veto по атрибутам — ПРОВЕРЕН КОДОМ, работает

Приём из разведки ([arXiv 2607.26298](https://arxiv.org/html/2607.26298): +32.8 п.п. purity):
если атрибут извлечён у позиции И у карточки и не совпал — отказ, а не «примерно».

Прогон на 30 найденных позициях замера 3:

```
принято по подтверждённому коду: 20
отказ по конфликту атрибутов:     1   (термометр: L=100 против L=80)
не подтверждено (мало атрибутов): 9
```

**Все 4 известные ошибки отсеяны.** Цена: 3 верные позиции тоже ушли в «не подтверждено».
Размен точности на полноту — осознанный и правильный для правила Ивана.

## Слой 2. Три варианта на выбор — РИСК, не проверяется кодом

Иван дословно: «проще поставим цифру, чем будем выбирать из двух-трёх». Он говорил про
выбор ВСЛЕПУЮ. Версия CEO — выбор с готовым разбором отличий. Возможно, это меняет ответ.
**Проверяется одним вопросом Ивану, не разработкой.**

## Слой 3. Автозапрос поставщикам — РЕАЛИСТИЧЕН, но с дырой и с риском

**Что есть:** распознавание счетов работает (118 счетов, 6635 позиций). Автозабор почты
есть в проекте Sasha, год на проде — переносится.

**Дыра:** `suppliers.contact_info` заполнено **0 из 46**. Адресов нет ни одного.

**Риск, который важнее кода:** нельзя слать с домена Арты. Массовая отправка с боевого
домена → чёрные списки → в спам падает ВСЯ почта компании, включая счета и письма директора.
Российские сервисы (Sniper Search) поэтому шлют со своего отдельного домена. Нужен отдельный
домен + SPF/DKIM/DMARC.

**Правовая рамка:** персональное деловое письмо юрлицу с запросом счёта — деловая переписка,
не реклама. Шаблонный веер на 200 адресов — уже реклама по 38-ФЗ без согласия. Граница
проходит по уникальности письма.

## Что показала разведка рынка

- **ТЗ-Мастер** (8 990 ₽/мес за 100 позиций) сам исключает из области применения: работы под
  заказ, индивидуальное изготовление, закрытые дилерские условия, непубличные цены.
  **Это ровно ядро задачи Арты.**
- **Готового решения «рассылает запросы → разбирает ответные счета» под инженерку в РФ нет.**
  Единственный заявляющий (МБС Group) — без цены и кейсов. Generic-игроки (Sniper Search)
  не заточены под спецификации объекта.
- **Отраслевого API прайсов** для инженерных сетей в РФ не существует.
- Ориентир из литературы: product matching в целом живёт в **30–70% F-measure**, на невиданных
  ранее позициях качество падает на 15–30%. Наши 47% на товарной части — внутри коридора.

## Приёмы, которые берём из разведки

| Приём | Что лечит | Сложность |
|---|---|---|
| Hard veto по атрибутам | L=100/L=80, SDR26/SDR11 — **проверено, работает** | низкая |
| Sparsity-порог (мало атрибутов → выше требование) | «Металл сортовой → хомуты» | низкая |
| Словарь Ду/DN/дюйм → один ключ (ISO 6708) | recall на запросах + veto на проверке | низкая |
| `quantulum3` для величин с единицами | извлечение атрибутов | низкая |
| Пороги по категориям, не общий | труба и термометр ведут себя по-разному | низкая |
| ETIM как список атрибутов для ОВиК/сантехники | «какие атрибуты вообще извлекать» | средняя, русской версии нет |

**Не берём:** дообучение моделей (нет размеченных данных, нужны тысячи пар), картиночную
ветку (у нас на входе строка, не фото), свой каталог с векторным индексом (карточки приходят
из веба поштучно).

## Как три слоя связываются в один поток

```
позиция спецификации
   ├─ есть код изделия и подтверждён на карточке ──→ цена ставится САМА (20 из 43)
   ├─ атрибуты разошлись ──→ ОТКАЗ, к поставщику
   ├─ атрибутов мало / не подтверждено ──→ ИИ объясняет, что нашлось ──→ список «оценка»
   └─ проектное оборудование и изготавливаемое ──→ ЗАПРОС ПОСТАВЩИКУ по почте
                                                        ↓
                                             ответный счёт ──→ парсер (уже работает)
                                                        ↓
                                             цена в смету (после проверки человеком)
```

Именно эта связка закрывает то, что рынок не закрыл: ТЗ-Мастер сдаётся на непубличных ценах,
а у нас непубличная цена уходит в почтовый запрос — и возвращается счётом, который система
уже умеет читать.

# РАЗДЕЛЕНИЕ СПЕЦИФИКАЦИИ — доработано и проверено на 5 спецификациях (21.08, поздний вечер)

## Зачем

Разделение — стержень решения. Каждая позиция получает квалификацию «откуда по ней может
взяться цена», и дальше идёт своей механикой. Инструмент не обязан решать все четыре — он
обязан честно назвать каждую.

## Что было сломано и починено

**1. Марка искалась в одном поле.** Парсеры кладут её куда придётся: в `19_8-24-ОВ` — в
`product_code`, в `spec.pdf` — в `characteristics` (`ШГ-50-30-1000`), в «Новой Самаре» — в
`manufacturer` (`TPLCPL2375L`, туда парсер положил артикул). Классификатор смотрел только
`product_code` и давал 0% на трёх спецификациях из четырёх.
**Фикс:** марка ищется ПО ПРИЗНАКУ во всех полях. Оказалось, 198 марок из 243 лежат прямо
в названии позиции.

**2. Типоразмер принимался за марку.** `DN20`, `Ду25`, `Ру16` проходили как марка изделия,
поиск уходил по диаметру и находил любой товар того же размера: «прямой DN20» → клапан Herz,
«Тройник ГОСТ 3262-75 DN25» → чугунный тройник другого типа.
**Фикс:** слитные типоразмеры исключены. Такие позиции уходят в слой «без марки», где
проверяются вето по характеристикам.

## Итог по 886 позициям пяти спецификаций

| Слой | Позиций | Доля | Механика |
|---|---|---|---|
| C. Марка изделия | 243 | **27%** | поиск + сверка марки на карточке |
| D. Без марки | 273 | 31% | поиск + вето по атрибутам + разбор ИИ |
| A. Изготавливается | 339 | 38% | расчёт по площади металла |
| B. Проектное | 31 | 3% | запрос поставщику |

**Доли резко разные по типу раздела — и это не шум:**

| Спецификация | Марка | Изготавливается |
|---|---|---|
| Вентиляция (spec.pdf) | 21% | **52%** |
| ВК Пристрой (водоснабжение) | 14% | **0%** |
| ОВ (19_8-24) | 46% | 19% |

В вентиляции половина спецификации — воздуховоды, которых нет в продаже как товара.
В водоснабжении их ноль. Один инструмент на этих разделах даёт разный результат, и без
разделения мы будем то обещать лишнее, то занижать себя.

## Находимость слоя «марка» — проверена на трёх спецификациях

| Спецификация | Результат |
|---|---|
| 19_8-24-ОВ (все 93 позиции слоя) | 63 из 93 — **68%**, 9,2 млн ₽ |
| spec.pdf + Новая Самара (выборка 30 настоящих марок) | 21 из 30 — **70%** |

**Слой переносится между спецификациями.** Это был главный вопрос: работает ли поиск, когда
марка вытащена из названия (`C11-300-500`) или из поля производителя (`TPLCPL2375L`), а не
лежит в отдельной колонке. Работает.

## Что НЕ решаем сейчас — и это осознанно

Изготавливаемое (38%) и проектное (3%) — локализованы, механика названа, но не строится.
Инструмент по ним говорит: «считается по площади» / «нужен счёт». Иван и так знает, что с
ними делать; ценность в том, что программа не молчит и не выдумывает.

Опора на цены прошлых закупок — **исключена из решения**. Цена в старом счёте устаревает,
номенклатура у поставщика меняется: вчерашняя позиция завтра закрывается другой.

## MVP

Прогон спецификации Ивана с разбивкой на четыре слоя; по слою «марка» цена ставится сама,
по остальным — честная пометка откуда её брать. Ожидаемое закрытие: **19–36% позиций
спецификации автоматически**, в зависимости от раздела (ОВ ближе к верхней границе,
вентиляция к нижней).
