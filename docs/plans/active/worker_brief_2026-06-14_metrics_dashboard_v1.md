## 1. Что делаем (одной фразой)
Одна страница на фронте, на ней 5 квадратов с цифрами + при наведении мышкой — короткое пояснение. Источник цифр — один новый ответ на сервере, который агрегирует данные по всем живым проектам.

**НЕ ДЕЛАЕМ в этой версии:** ленту событий, привязку к действиям, ИИ-комментатор, телеграм-сводку. Это позже отдельными итерациями.

## 2. Минимальный объём (фичи)
### 2.1 Бэкенд — один новый эндпоинт
`GET /api/metrics/dashboard` — отдаёт массив объектов, один на проект:
```
[
  {
    "project_id": 6,
    "project_name": "тест для обучения",
    "real_name_hint": "Сокольи горы ВК (см. reflection_2026-06-14_sokoliy_vk_is_project_6_discovered)",
    "spec_total": 377,
    "with_any_candidate": 333,
    "without_candidate": 44,
    "memory_top1": 47,
    "llm_top1": <число>,
    "name_sim_top1": <число>,
    "operator_confirmed": 268,
    "accuracy_at_1_status": "tautology" | "honest" | "n/a",
    "accuracy_at_1_value": null
  },
  ... остальные проекты
]
```

Логика расчёта:
- `with_any_candidate` = `items.filter(it => it.matches?.length > 0).length`.
- `without_candidate` = `spec_total - with_any_candidate`.
- `memory_top1` = строки, где top-1 по `confidence` имеет `matchType === 'learned_rule'`.
- `llm_top1` = тот же отбор top-1, `matchType === 'llm_suggestion'`.
- `name_sim_top1` = тот же отбор top-1, `matchType === 'name_similarity'`.
- `operator_confirmed` = строки, где есть `matches.some(m => m.isConfirmed)`.
- `accuracy_at_1_status` = **в этой версии всегда `"tautology"`**. Это явный честный маркер «текущий способ замера ложный, потому что API скрывает rivals у confirmed-матчей». Карточка на фронте покажет «честное число позже» вместо цифры. Запись `"honest"` будет позже когда сделаем отдельную правку API (отдельный бриф).
- `accuracy_at_1_value` = `null` (потому что tautology).

**Фильтрация проектов:** возьми только проекты, у которых `spec_total > 100` ИЛИ `operator_confirmed > 50` (живые, не тестовые песочницы). Чтобы тестовые «регрессия 1» и «A.2 isScan test» не засоряли таблицу. Уточни хвост условия эмпирически — таблицу должны заполнить пр.6, 11, 12, 13.

**Время выполнения**: ≤ 2 секунды на 4 проекта. Если будет медленнее — добавь кэш на 60 секунд (например через `node-cache` или просто map с TTL).

**Кодстайл**:
- Без хардкода имён проектов (`feedback_no_hardcode`).
- Параметризованные SQL (если используешь прямой SQL).
- Никаких изменений существующих эндпоинтов — только новый.

### 2.2 Фронтенд — одна новая страница
Путь: `/metrics` (или, если уже занят, `/dashboard`). Добавь ссылку на неё в основной навигации.

Содержимое:
- Заголовок страницы: **«Главные показатели проектов»** (короткое название, без жаргона).
- Под заголовком — таблица: одна строка = один проект, колонки = 5 карточек. Альтернатива: pivot — 5 строк-карточек, столбцы — проекты. Выбери что читабельнее (с учётом 4 проектов — обе формы ок).

**5 карточек (короткое имя на карточке + при наведении мышкой — полное пояснение):**

1. **«Что видит оператор»**
   - Цифра: `with_any_candidate / spec_total` (процент) + абсолютное число «X из Y»
   - Подсказка при наведении: *«Сколько строк сметы получают хоть какой-то вариант от системы. Если мало — оператор открывает проект и видит сплошную пустоту. Чем выше — тем меньше работы вручную. Цель: 90% и выше.»*
   - Сейчас (06-14, для проверки в тестах): пр.6=88.3%, пр.11=92.1%, пр.12=41.9%, пр.13=37.7%.

2. **«Сколько раз система угадывает с первого раза»**
   - **В этой версии — плашка «Честное число будет позже».** Объяснение в подсказке: *«Сейчас сервер для подтверждённых строк отдаёт только подтверждение, скрывая других кандидатов. Поэтому замер всегда даёт 100% — это враньё. Чиним отдельной правкой.»* — короче можно. Главное — не врать.
   - Цель: средняя по проектам ≥ 80%.

3. **«Сколько работы делает Память»**
   - Цифра: `memory_top1 / with_any_candidate` (процент) + абсолютное число
   - Подсказка: *«Доля строк, для которых система предложила правильный аналог из своей записной книжки, без обращения к платному ИИ. Чем выше — тем дешевле и быстрее работа. На зрелых проектах должна расти.»*
   - Сейчас: пр.6=14%, пр.11=39%, пр.12=10%, пр.13=5%.

4. **«Сколько раз система уверенно ошиблась»**
   - **В этой версии — плашка «нужен сбор данных от оператора».** Сейчас в системе нет события «оператор отклонил уверенный матч». Карточка пустая с поясняющей надписью.
   - Этот сбор — отдельная следующая задача.

5. **«Сколько кликов сделал оператор»**
   - **В этой версии — плашка «нужен сбор событий».** Аналогично карточке 4.

**Визуальный стиль (кратко):**
- Каждая карточка — квадрат с заголовком сверху и большой цифрой посередине.
- Цвет фона по правилу:
  - Зелёный (≥80% / целевое значение) — карточка 1
  - Жёлтый (50-79%) — карточка 1
  - Красный (<50%) — карточка 1
  - Серый — плашка-карточки (2, 4, 5)
- Без иконок, без графиков, без анимации. **Минимально.**
