### Уточнения по каждому проекту

**Сокольи (proj 1 — held-out, самый чистый):**
- Pool = реальные строки счетов (ЦИС, Крона, Юнирайз, СМЛ).
- Baseline (AI-OFF, без KB) = 0% (max sim 0.48 < порог 0.60 для «чужих» имён).
- KB история = 17/28 bridgeable паспортами → 46.4%@1.
- AI-ON = 89.3% (Gemini справляется с трудными парами).
- Результаты из существующих файлов `verity-sokoliy-endtoend-result-*.json`.

**Ласточка (proj 11 — held-out, 150 подтверждений оператора):**
- Pool = 279 уникальных товаров из 6 счетов (ИТЕСА, АС ГРУПП, прочие).
- AI-OFF = 2.7% (слабое текстовое сходство: «Конвектор напольный Tepla Neo Expo 156x320» vs «Конвектор TEPLA Neo Expo 156(В)х320(Г) - 4,581 (К; НР 3/4 УТ; Лев; СП; КлМ; Т/п...»).
- KB = 3.3% — практически нет улучшения. Каталог (из ВК/Самара/Совжи/Престиж) почти не покрывает домен Ласточки (конвекторы TEPLA, фитинги трубы из сшитого полиэтилена ПЭ-Кс).
- AI-ON = **26.7%** — LLM даёт основной прирост; но 73% остаются не сопоставлены даже через LLM.
- **Кавычка**: "confirmed ≠ verity строго" — confirmed = оператор вручную выбрал, не всегда самый похожий товар. 150 пар — честный проксимальный наземный. Но дефицит KB-покрытия = реальный.

**Исторические эталоны (4-split):**
- Пары с аналогом = только 5.7–46.5% строк (остальные — singles, аналог не указан).
- Совжи ВК 93.9%: **WOW-кандидат** (см. раздел C). KB знает 98 обучающих пар → bridging работает для 31/33 тест.
- Совжи ОВ 44.4%: умеренный KB-эффект. 36 тест-пар, пул=91 аналогов. Ряд промахов — rank=2 (пороговая ситуация).
- Новая Самара 40%: малый выборка (5 тест-пар). 2 из 3 промахов — нет KB-паспорта для NED SMEX и ГОСТ-ссылок.
- Престиж 5.3%: слабый KB-перенос. Специфика — комбо-файл (25 колонок, три датированных прайса, смешанный формат), многие аналоги = конкретные позиции прайс-листа (не стандартные имена), KB из других доменов не перекрывает.

## C. WOW-кандидат

**Совжи ВК: 93.9% durable @1/@3** при KB-режиме.

- 33 тест-пар из 131 total, пул = 29 аналогов.
- KB знает 98 обучающих пар того же проекта → KB мост работает для 31 из 33 тест-пар.
- **Реальность для показа оператору:** тест «по закрытой книге» внутри одного проекта (не cross-project). Показывает, что как только KB насыщена примерами домена, система сама правильно сопоставляет ~94% позиций — **без оператора, без LLM**.
- **Ограничения:** пул = 29 аналогов (а не сотни строк реального счёта). Если пул расширить до полного инвойса, точность упадёт. Это симуляция «знаю домен → сопоставляю», не end-to-end сквозной.
- **Нет WOW-кандидата с end-to-end пулом без KB**: Ласточка = 26.7% AI-ON / 3.3% durable — слишком низко. Сокольи = 46.4% durable — хорошо, но не «вау-процент» для оператора (оператор видит, что 53.6% всё равно надо трогать).

**Вывод по WOW:** Совжи ВК — кандидат если дать оператору смотреть на проект с уже накопленным KB (90+ обучающих пар того же типа товаров). Для Ласточки — дефицит покрытия, нужна KB из OV-конвекторов.

## D. Потолок текущих данных

| Категория промахов | Пример | Источник | Чинится текущими данными? |
|-------------------|--------|----------|---------------------------|
| **Нет KB-паспорта (другой бренд/модель)** | Сокольи: «Элита КП», «ДН 674922» (PDF-поставщики, не в KB) | Нужны новые данные или PDF-чтение | **НЕТ** — нужны новые пары |
| **Разные домены** | Ласточка: TEPLA Neo (конвекторы), Uponor/Rehau (трубы ПЭ-Кс) | KB из ВК не переносится в ОВ-конвекторы | **НЕТ** — нужны пары из OV/конвектор-домена |
| **ГОСТ-ссылки как аналог** | Новая Самара: «гост 17376-2001», «гост 17374-2001» | Это номера стандартов, а не товар | **НЕТ** — нужны реальные имена товаров |
| **Пороговый промах rank=2** | Совжи ОВ: «Кран шаровый ф15мм BVR-R» rank=2 | sim-тайбрейк разделяет DN15/DN20 варианты | **ДА** — C2/DN-уточнение или расширенный KB |
| **Специфика Престижа** | «Счётчик воды ЭКО НОМ», «Манометр МП4-У» | KB из Самара/Совжи нет таких позиций | **НЕТ** — нужны пары ВК-Престиж или аналоги |
| **Огнезащита / спецоборудование** | Совжи ОВ: «Огнезащитное покрытие фольгированное» → «треб. не менее EI 120» | Это требование, не товар | **НЕТ** — структурный пробел (не-товарная строка) |

**Итог потолка:**
- ~60% промахов = дефицит данных (новые домены, новые поставщики, новые категории).
- ~20% промахов = структурный пробел (ГОСТ-ссылки, ТЗ-требования вместо имён товаров — нельзя сматчить ни KB, ни LLM на 100%).
- ~20% промахов = пороговые (rank=2, близкие варианты) — чинится рычагами DN/C2/sim-тайбрейк.

## Воспроизведение

```bash
# Сокольи (все режимы)
cd ckb2
node scripts/verity-sokoliy-endtoend.mjs                # AI-OFF, 0%
node scripts/verity-sokoliy-endtoend.mjs --kb-history   # durable 46.4%
node scripts/verity-sokoliy-endtoend.mjs --kb-history --c2  # C2 delta (=46.4%, нет эффекта)
OPENROUTER_API_KEY=$(grep ^OPENROUTER_API_KEY= ../budget-automation/.env | cut -d= -f2-) \
  node scripts/verity-sokoliy-endtoend.mjs --ai-on      # AI-ON 89.3%

# Ласточка
node scripts/verity-lastochka.mjs --ai-off              # 2.7%
node scripts/verity-lastochka.mjs --ai-off-kb           # 3.3%
OPENROUTER_API_KEY=$(grep ^OPENROUTER_API_KEY= ../budget-automation/.env | cut -d= -f2-) \
  node scripts/verity-lastochka.mjs --ai-on             # 26.7%

# Исторические (train/test split, каждая 4-я пара = тест)
node scripts/verity-historical.mjs --aioff              # baseline 0-2.8%
node scripts/verity-historical.mjs --aioff-kb           # KB 5-94%
```

## Технические примечания

1. **DL path fix** (2026-06-08): эталонные файлы переехали из `Downloads\` в `Downloads\Таблицы\`. Исправлено в `bootstrap-canonical-kb.mjs` (DL='...Таблицы\\') и `verity-sokoliy-endtoend.mjs` (FILE). Исторические результаты (b839a0f) были получены до переезда и остаются валидными — KB-базис идентичен.

2. **ckb2 no .env**: worktree `ckb2` не имеет `.env`. AI-ON режим требует явной передачи `OPENROUTER_API_KEY` через env (команды воспроизведения выше). В `verity-lastochka.mjs` добавлено автоматическое чтение key из `../budget-automation/.env`.

3. **Historical pool = etalon-analogs**: для исторических проектов пул = уникальные имена аналогов из эталона, а не строки реального счёта (счетов нет). Поэтому пул меньше реального (7–91 против сотен строк). Цифры 40-94% нельзя прямо сравнивать с Сокольи (реальный счёт-пул).

4. **Caveats**: Совжи ВК 93.9% = within-project KB (обучен на 75% тех же пар). Это "знание домена", не кросс-проектный перенос. Кросс-проектный перенос — Сокольи 46.4% (верифицирован как "по закрытой книге", `reflection_2026-06-08_canonical_kb_history_transfer.md`).
