## Контракт (зачем)
Ключевая величина = `unit_price_with_vat` = цена/ед **с НДС (×1 — это уже сделано фичей #1)** ×
**со скидкой, если скидка есть**. Эта фича закрывает **форму A скидки**: когда в счёте есть
конкурирующие колонки-итоги «Сумма без скидки» и «Сумма (со скидкой / с НДС)», парсер ОБЯЗАН
выбрать **итоговую (после скидки)**, иначе бюджет **завышается**.

## Проблема (доказана кодом)
Скорер колонок `scoreVatDiscount` (`backend/src/services/pdfParser.ts:55`) + зеркало
`_score_amount_column` (`scripts/extract_invoice_table.py:115`) сейчас:
```
if (/скидк/) score += 30;     // слепо +30 за ЛЮБОЕ упоминание скидки
```
⇒ `Сумма без скидки` получает **+30** (от подстроки «скидк») и **бьёт** `Сумма с НДС` (+20) →
выбирается ДО-скидочная колонка → завышение. Логика «без скидки» забыта (для НДС она есть: −20).

## Фикс (зеркало логики НДС, синхронно TS+Python)
```ts
// TS — pdfParser.ts, в scoreVatDiscount, заменить строку `if (/скидк/) score += 30;`
const withoutDiscount = /без\s+скидк/.test(lower);
if (withoutDiscount) score -= 20;
else if (/скидк/.test(lower)) score += 30;
```
```python
# Python — extract_invoice_table.py, в _score_amount_column, заменить блок `if re.search(r'скидк', text): score += 30`
without_discount = re.search(r'без\s+скидк', text) is not None
if without_discount:
    score -= 20
elif re.search(r'скидк', text):
    score += 30
```
Результат: `Сумма без скидки` → −20 (проигрывает `Сумма с НДС` +20); `Сумма со скидкой` → +30;
`Сумма` (без слова «скидк») → 0 (без изменений). Ничего, кроме discount-ветки скорера, не трогать.
