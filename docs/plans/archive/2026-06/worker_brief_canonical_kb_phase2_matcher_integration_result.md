## Решение ре-нормализации (пункт 1 брифа)

**Подход: eval-DB с пустыми синонимами = согласован с бутстрапом.**

Бутстрап каталога (фаза 1) работал с ПУСТЫМИ таблицами синонимов → `alias_norm` = normalizeForMatching без синонимов.  
Verity-харнесс создаёт ПУСТУЮ temp-DB → та же нормализация → ключи совпадают.  
Конфликт нормализации реален только при деплое в прод (синонимы непустые) — это CARRY на фазу деплоя (ре-бутстрап с прод-синонимами).

## Архитектура интеграции (пункт 2)

### Тир 2.5 — canonical KB атрибутный мост

**Место:** между тиром 2 (learned rules) и тиром 3 (name_similarity) в `matchSpecItems`.

**Предвычисление (один раз перед outer loop):**
```
invKbAttrCanons: Map<invId, Set<canonicalId>>  ← getCanonicalByAttributes(inv.passport)
invKbAliasId:   Map<invId, canonicalId>        ← getCanonicalByAlias(inv.name)
```

**Per-spec (outer loop):**
```
specKbAttrIds: number[]   ← getCanonicalByAttributes(spec.passport)
specKbAliasId: number     ← getCanonicalByAlias(spec.name)
```

**Inner loop (per spec×invoice пара):**
- **Alias-хит:** оба → один canonical → `conf = KB_ALIAS_HIT_CONFIDENCE = 0.86`
- **Attribute-хит:** пересечение canonical-ID множеств → `conf = 0.78 + rawNameSim * 0.08`  
  Tiny sim-тайбрейк (0..0.08) воспроизводит string-sim ранжирование офлайн-смока.

**Graceful fallback:** если таблицы KB не созданы → `kbEnabled = false` → тир пропускается без ошибки.

## Разбор промахов (16 из 28 не попали в @1)

### Группа A: тип-синоним "клапан" ≠ "кран" (≈6 пар R16/17/18/19/119/281)

Spec: "Клапан шаровый … Ø15" — want: "Кран шаровой … DN15".  
`typeMatches("клапан", "кран")` = false → KB атрибутного моста нет.  
`getStructuralScore` = -1 (марки-коды VT vs LD конфликтуют).  
→ **CARRY:** добавить "клапан шаровой"↔"кран шаровой" в `construction_synonyms`.

### Группа B: неверный кандидат на #1 — ложный KB-хит (≈4 пары)

R163/409/410/4: KB нашёл товар с тем же типом/DN, но другой бренд/электропривод.  
Конфидентный (0.88+) неверный ответ выдавливает правильный (правильный не в KB или ниже).  
→ **CARRY:** более узкое `featuresAgree` или явный типовой фильтр для фаза-3.

### Группа C: труба полипропиленовая vs арм. стекловолокном (≈6 пар R83/84/85/86/247/312)

struct=-1 (материал/марка конфликт PN20 vs SDR7.4), KB не матчит.  
→ **CARRY:** атрибут материала в паспорт.
