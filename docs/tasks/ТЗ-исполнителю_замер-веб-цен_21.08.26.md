# Задание исполнителю: проверить, находятся ли цены на инженерное оборудование в интернете

**Дата:** 21.08.2026
**Формат:** разовая работа, проверка гипотезы. Не разработка продукта.
**Что на выходе:** таблица с числами + короткий вывод + скрипт, которым вы это получили.

---

## 1. О чём проект

Наш клиент — компания, которая монтирует инженерные сети (вентиляция, отопление,
водоснабжение). Когда им приходит спецификация на объект, снабженец должен понять:
**сколько это будет стоить и стоит ли вообще идти в этот тендер.**

Сегодня он делает это руками: берёт позицию из спецификации, идёт в браузер, ищет,
у кого она есть, смотрит цены, переходит к следующей. Десятки позиций, много часов.

Мы хотим повторить этот путь программой: взял позицию → нашёл, у кого есть → собрал
цены → сравнил. Не для закупки, а **для оценки: адекватный ценник, чтобы принять
решение по тендеру.** Точность до копейки не нужна — нужна честная рыночная цена.

Прежде чем это строить, надо проверить одну вещь. О ней и задание.

---

## 2. Что именно надо проверить

**Вопрос:** если взять реальную позицию из спецификации и поискать её в интернете
программой — найдётся ли цена, и насколько она отличается от той, по которой
компания реально купила этот товар?

Это важно, потому что клиент покупает у своих поставщиков со скидкой. Если открытая
веб-цена окажется, скажем, на 40% выше реальной закупочной, и разброс будет хаотичный —
считать смету по вебу нельзя, и продукта у нас нет. Если отклонение стабильное
(например, веб стабильно дороже на 5–12%) — вводим поправочный коэффициент, и всё
работает.

**Нам нужны два числа:**

1. **Покрытие.** На скольких позициях из выданного списка удалось найти цену в вебе.
2. **Отклонение.** Насколько найденная цена отличается от фактической — по каждой
   позиции в процентах, плюс медиана и разброс по всему списку.

Никакого продукта, интерфейса и базы данных делать не нужно. Нужны числа и вывод.

## 3. Что мы даём

**Файл `positions.csv` — 30 позиций** из реальных счетов клиента (закупки за
октябрь–декабрь 2025). Колонки:

| Колонка | Что это |
|---|---|
| `id` | наш внутренний номер позиции |
| `article` | артикул производителя (например `MJ60`, `AF76`, `TMK108`) |
| `name` | наименование как в счёте |
| `unit` | единица измерения |
| `fact_price` | **фактическая цена за единицу, по которой купили** (в рублях, с НДС) |

Артикулы конкретные — такие ищутся точно, без гадания по названию.

**Доступ к поиску.** Мы выдаём ключ Yandex Search API (наш аккаунт, наши расходы).
Стоимость прогона копеечная: 30,5 ₽ за 1000 запросов, весь ваш замер — меньше рубля.
Если на момент старта ключ ещё не готов — скажем отдельно.

Доступа к нашему коду и базе не даём и он не нужен: задача автономная, вход — csv,
выход — csv.

## 4. Что мы уже проверили — не тратьте на это время

Это проверено нами лично замерами 11–14.08.2026, переоткрывать не нужно:

- **Бесплатных каналов поиска нет.** Яндекс обычным запросом — капча сразу. Яндекс
  через браузерную автоматику (Playwright/stealth) — капча со второго запроса даже
  с паузами 25–40 секунд. DuckDuckGo — работает десяток запросов, потом отдаёт
  HTTP 202 с маркером «anomaly» и блокирует. Bing — программе ссылок не отдаёт вовсе
  (всё на JS). go.mail.ru — пусто.
- **Парсить выдачу Яндекса напрямую нельзя** — запрещено лицензией (п. 6.6) и
  условиями Search API (п. 3.5). Легальный путь стоит копейки, экономии от нарушения
  нет. Работаем только через официальный Search API.
- **Карточки магазинов открываются обычным HTTP-запросом** (проверено на polteplov.ru,
  samara.proconsim.ru, etm.ru): HTTP 200, цена лежит в разметке schema.org / JSON-LD.
  **Браузерная автоматизация для чтения карточки не нужна** — обычного `httpx`/
  `requests` достаточно.
- **Сайты с личным кабинетом (ELF, Лунда, Неватом, Русклимат) в этой задаче не нужны** —
  нам хватает открытых цен. У ELF и Лунды `robots.txt` запрещает `/search`, у ELF ещё
  и любой URL с параметром; ELF отдаёт автоматике капчу. Туда не ходим.

Итого рабочая схема, которую надо реализовать: **Search API отдаёт список магазинов
по артикулу → карточку каждого магазина забираем обычным HTTP → достаём цену из
schema.org.**

## 5. Что считается выполненной работой

1. **`result.csv`** — по строке на позицию: артикул, наименование, фактическая цена,
   найденная веб-цена, ссылка на страницу, где она найдена, магазин, отклонение в %.
   Если цена не нашлась — так и пишем, с причиной (не нашлось в выдаче / в карточке
   нет цены / «по запросу» / товар не тот).
2. **Короткий вывод, 5–10 строк:** на скольких позициях из 30 цена нашлась; медиана
   отклонения; какой разброс; ваша оценка — можно ли по такому механизму считать
   смету или мешает что-то конкретное.
3. **Скрипт**, которым вы это сделали (Python), чтобы мы могли повторить прогон сами.

**Обязательное требование к честности данных:** цена должна быть взята со страницы
именно этого товара, а не «похожего». Если не уверены, что нашли тот самый артикул —
помечайте позицию как ненайденную, а не подставляйте близкую. Одна подставленная
«похожая» цена портит весь замер: мы принимаем по нему решение, строить продукт или нет.
