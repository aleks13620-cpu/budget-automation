# Хендовер для Сергея — модуль внешних цен поставщиков (`price-harvester`)

Документ передаёт состояние модуля «сбор цен поставщиков из внешних источников»:
что уже сделано, что пробовали (и с каким результатом), куда смотреть дальше и как
это увидит оператор, когда сбор заработает на полную мощь.

Заказчик: Алексей. Система: budget-automation (инженерные сети). Модуль отдельный
(Python), рядом с TS-бэкендом, интеграция через общую SQLite.

---

## 1. Цель модуля

По позициям из спецификаций/счетов сам находить актуальные цены в интернете
(официальные прайсы поставщиков и производителей) и складывать в базу — чтобы
система показывала «где дешевле» относительно цены из счёта.

**Фаза 1 (сделана):** результат отдельным отчётом, бэкенд и матчинг НЕ трогаем.
**Фаза 2 (на будущее):** показать внешние цены прямо в приложении.

---

## 2. Что уже сделано (готово и проверено)

- **Модуль `price-harvester/`** — конвейер из 6 шагов, запуск одной командой:
  `python src/run.py --category арматура --limit 8`.
  1. `build_purchase_list` — список закупки из `specification_items` + база (цена/поставщик из счёта);
  2. `resolve_sources` — какие источники к каким позициям (`config/sources.yaml`);
  3. `collect_prices` — сбор: гейт robots/ToS → снять сырьё → парсить офлайн → скоринг;
  4. `load_db` — идемпотентная укладка в таблицу `external_prices`;
  5. `qa_report` — Completion-QA (сколько нашли / заблокировано / пусто);
  6. `compare` — отчёт «где дешевле» → `out/comparison.{xlsx,csv,json}`.
- **Построено на навыке open-data-harvester** (его ядра `rest_client`/`feed_xml`
  скопированы в `harvester/`, чтобы работало на проде без `~/.claude/skills`).
- **Подключён реальный источник VALTEC** — официальный XLSX-прайс (РРЦ),
  **4151 позиция, 25 разделов**. Рецепт `price_xlsx` (новый, в навыке его не было):
  ссылка на свежий .xlsx берётся автоматически со страницы прайса (`price_page`),
  размеры в дюймах конвертируются в Ду (1/2″→DN15, 1″→DN25…).
- **Этика встроена:** перед сбором проверяется `robots.txt`; источник без
  `robots_checked:true`/`tos_ok:true` блокируется кодом. Провенанс на каждой цене
  (источник, URL, дата среза, валюта, НДС).
- **Идемпотентность** по бизнес-ключу (источник|позиция|артикул/имя|единица|дата):
  повтор не задваивает; очистка среза убирает «осиротевшие» строки.
- **Не тронуты:** распознавание счетов/спецификаций (GigaChat), матчер, схема бэкенда.

Артефакты последнего прогона — в `out/` (`comparison.xlsx`, `qa_report.md`).
Подробный runbook — в `README.md`.

## 3. Что попробовали — и что получилось (честно)

| Источник | Тип товара | Результат |
|---|---|---|
| **VALTEC** (официальный XLSX-прайс) | каталожная арматура, фитинги, счётчики | ✅ **Работает.** 4151 позиция; по «тип+размер» отдаёт кандидатов с ценой, диапазоном и ссылкой. Примеры (реальные): «Кран шаровой 1/2″» VT.250.N.04 = 779₽; «Водосчётчик 3/4″» VLF-20U = 2979₽; «Фильтр сетчатый 1″» H.157.06 = 365₽. |
| **ВЕЗА** (veza.ru) + реселлеры | вентиляция: клапаны КПУ | ❌ **Цены нет нигде.** veza.ru — кнопка «Рассчитать» (калькулятор `/raschet/` запрещён robots); реселлеры smtrading.ru и atlantcompany.ru — «по запросу». |

**Главный вывод (важно для всего проекта).** Внешний прайс-мониторинг делится надвое:

- ✅ **Каталожные товары с фиксированной ценой** — арматура, фитинги, трубы,
  изоляция, счётчики, краны, насосы стандартные. Тут модуль работает.
- ❌ **Проектное конфигурируемое оборудование** — клапаны КПУ, приточные установки,
  шумоглушители под размер. Публичной цены НЕТ в принципе (считается под заказ) →
  тут остаётся сравнение по счетам/КП, которое система уже умеет.

**Про точность сопоставления.** У разных брендов имена расходятся, поэтому точное
совпадение варианта между брендами редко. Модуль надёжно опознаёт **тип товара
(кран/фильтр/счётчик) + размер (DN)** и показывает ближайший вариант, **диапазон
цен** и **точность** (match_score). Аксессуары («…для счётчика», «фильтроэлемент»)
отбрасываются. **«Экономию %» заявляем только при уверенном совпадении** (score ≥ 0.6) —
иначе помечаем «похожие варианты, проверить». Точное сопоставление варианта — задача
матчинга бэкенда (правила + LLM); этот модуль ДОСТАВЛЯЕТ цены и кандидатов.

Практика: источник даёт максимум пользы, когда держит те же бренды/товары, что и
спецификация. Пример: прайс VALTEC точно ложится на спеку в VALTEC-арматуре; на
«чужих» брендах (Пульсар/ФММ) выходит диапазон по типу+размеру.

## 4. Как добавить источник (механика)

1. **Чек-лист этики (обязателен).** Открыть `https://<домен>/robots.txt` — путь к
   выгрузке не должен быть запрещён. Прочитать ToS — нет ли запрета на авто-сбор.
2. В `config/sources.yaml` добавить источник: `recipe` + адрес, выставить
   `robots_checked: true`, `tos_ok: true`, `enabled: true`.
3. Прогнать пилот на 3–5 позициях, глазами проверить `qa_report.md` и
   `comparison.xlsx`, и только потом масштабировать.

**Рецепты (по приоритету «вежливости»):**
- `price_xlsx` — официальный XLSX-прайс (как Valtec). **Предпочтительно.**
- `feed_xml` — YML/XML-фид магазина/каталога. Тоже «парадная дверь».
- `rest_html` — карточки на сайте. Нужен индивидуальный парсер; на пилоте не используем.
- `stealth_browser` (из навыка, ставится отдельно) — если за антиботом. Капча/бан =
  стоп-сигнал, не «дожимай».

## 5. На каких поставщиков смотреть дальше

Логика: брать **каталожные** источники под **коммодити-позиции** спецификаций
(там, где есть фиксированная цена). По категориям из реальных проектов:

- **Арматура (краны, фильтры, редукторы, обратные клапаны):** VALTEC уже есть; можно
  добавить аналогичные прайсы (например, дистрибьюторы с YML/XLS).
- **Счётчики воды (Пульсар, ВСХ/ВСГ):** найти официальный прайс производителя/дилера
  (XLS или карточки). Пульсар — НПП «Тепловодохран».
- **Трубы/фитинги:** для ПНД/ПЭ канализации и стальных — найти прайс профильного
  производителя (у Valtec — металлопласт/PPR, это другой материал).
- **Изоляция (K-Flex, ИТЕСА):** у дилеров K-Flex обычно есть прайсы XLS.
- **Вентиляция конфигурируемая (КПУ, установки):** внешних цен НЕТ — не тратить время,
  оставляем сравнение по счетам/КП.

**Как искать у нового поставщика:** (1) страница «прайс-лист»/«скачать прайс»
(XLS/CSV) — лучший вариант; (2) YML-фид (часто `/upload/…/*.yml`, смотри `robots.txt`
и `sitemap.xml`); (3) карточки с ценой. Если везде «по запросу» — товар проектный,
внешнего источника нет.

## 6. Что доделать (задачи)

1. **Пометка «проектный товар — публичной цены нет».** Классификатор по категориям
   (вентиляция-конфигуратор и т.п.), чтобы отчёт отличал «не нашли (должны были)» от
   «цены нет в природе». Сейчас оба показываются как пусто.
2. **Больше каталожных источников** под бренды спеки (см. §5).
3. **Фаза 2 — показать в приложении.** Проекция выбранных `external_prices` в
   `price_list_items` под служебный `price_lists` → существующий матчер увидит внешние
   цены без правок кода (обратимо: удалил служебный прайс — чисто). Включать ТОЛЬКО
   после согласования: критический путь проекта = качество матчинга.
4. **Связать с матчером бэкенда** для точного варианта (правила/LLM), а не только
   тип+размер — когда дойдут руки.

## 7. Как это увидит ОПЕРАТОР, когда парсер заработает на полную мощь

Сценарий (Фаза 2, в приложении):

1. Оператор открывает проект, где уже загружены спецификация и счета.
2. Нажимает **«Собрать внешние цены»**. Система проходит по позициям, тянет цены с
   настроенных источников (вежливо, с паузами) — это фон, видно прогресс.
3. Открывается экран **«Где дешевле»** — таблица по позициям спецификации:

   | Колонка | Что показывает |
   |---|---|
   | Позиция | наименование + размер (DN) |
   | Кол-во | из спецификации |
   | Цена из счёта | если позиция уже была в счёте (база сравнения) |
   | Лучшая внешняя | минимальная сопоставимая цена (с НДС) |
   | Источник | у кого/где (логотип/имя), **ссылка** на карточку/прайс |
   | Диапазон рынка | от–до по «тип+размер» (видно разброс) |
   | Экономия | % к цене из счёта — **только при уверенном совпадении** |
   | Статус | 🟢 точное совпадение · 🟡 похожее — проверить вариант · ⚪ проектный товар (цены нет) · ⬜ не найдено |
   | Дата цены | когда снят срез (свежесть) |

4. **Фильтры:** показать только где есть экономия; по категории; по источнику; только
   «проверить вариант».
5. **Действия по строке:** открыть ссылку-источник; принять внешнюю цену; пометить
   «проверено». Внизу — **итог: суммарная потенциальная экономия по проекту**.

Принципы вывода (уже заложены в данных модуля):
- честность: пусто = «не нашли/проектный товар», цену НЕ выдумываем;
- у каждой цены паспорт (источник, ссылка, дата, НДS) — всё проверяемо;
- «экономия %» — только когда совпадение уверенное; иначе «похожее, проверить».

Наглядный макет этого экрана приложен отдельно (показан Алексею).
