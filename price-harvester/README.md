# price-harvester — сбор цен поставщиков из внешних источников

Отдельный Python-модуль рядом с TS-бэкендом budget-automation. По позициям из
спецификаций/счетов находит актуальные цены в интернете (официальные сайты
поставщиков и производителей, YML-прайсы, B2B-агрегаторы) и складывает их в общую
SQLite — чтобы система могла сравнивать «где дешевле».

Построен на навыке **open-data-harvester** (его рецепты вендорно скопированы в
`harvester/`, чтобы модуль был самодостаточным на проде): `rest_client` (HTTP с
ретраями/кэшем/провенансом), `feed_xml` (разбор YML/XML-фидов).

> **Фаза 1 (текущая).** Результат — ОТДЕЛЬНЫЙ отчёт (`out/comparison.*`,
> `out/qa_report.md`) и таблица `external_prices`. В `price_list_items` ничего не
> пишем — критический путь матчинга НЕ трогаем. Бэкенд не переписываем: только
> добавляем свою таблицу (`CREATE TABLE IF NOT EXISTS`) и читаем существующие.

## Карта данных: откуда беру → куда пишу

```
specification_items (позиции)  ──┐
invoice_items + suppliers ───────┤ ШАГ 1  →  out/purchase_list.json
(цена/поставщик из счёта = база) │
                                 ▼ ШАГ 2  →  out/source_plan.json (что у кого искать)
              open-data-harvester (ШАГ 3): robots/ToS → снять сырьё → парсить офлайн
                                 ▼
                          external_prices (ШАГ 4, идемпотентно, с провенансом)
                                 ▼ ШАГ 5  →  out/qa_report.md   (Completion-QA)
                                 ▼ ШАГ 6  →  out/comparison.{json,csv,xlsx}  («где дешевле»)
```

## Установка

```bash
cd price-harvester
python -m pip install -r requirements.txt
cp .env.example .env          # при необходимости поправь BUDGET_DB_PATH / параметры
```

`.env` (главное):
- `BUDGET_DB_PATH` — путь к общей SQLite (по умолчанию `../database/budget_automation.db`);
- `PROJECT_ID` — пусто = берётся реальный проект с макс. числом позиций (тестовые исключаются);
- `PILOT_LIMIT` (5), `PILOT_CATEGORY` (пусто = счётчики+арматура+отопление);
- `MIN_DELAY_SEC` (2.0) — вежливая пауза между запросами к одному источнику.

## Запуск

**Пилот (3–5 позиций для ПРОВЕРКИ ТОЧНОСТИ перед полным прогоном):**
```bash
python src/run.py --category арматура --limit 8
```
По умолчанию включён реальный источник **VALTEC** (`config/sources.yaml` → `valtec`):
официальный XLSX-прайс (РРЦ), ~4150 позиций, 25 разделов. Офлайн-образец
(`sample_engineering`) выключен — включи его (`enabled: true`) для проверки без сети.

Полезные варианты:
```bash
python src/run.py --project-id 12 --limit 5
python src/run.py --category арматура --limit 8
python src/run.py --steps build,resolve            # только часть шагов
python src/run.py --steps load                     # перезалить (проверить идемпотентность)
```

## Как читать результат

- `out/qa_report.md` — **Completion-QA**: по скольким % позиций нашлась ≥1 внешняя
  цена, сколько источников заблокировано, какие позиции пусты. Пустая позиция
  ПОМЕЧЕНА (не нашли/заблокировано), а не заполнена выдуманной ценой.
- `out/comparison.xlsx` (и `.csv`/`.json`) — **«где дешевле»**: по каждой позиции
  цена из счёта, лучшая внешняя (приведённая к цене с НДС), источник, ссылка,
  экономия %. Пример строки в консоли:
  `Воздушный клапан 700x400: счёт 14008₽ / sample_engineering 12500₽ → экономия 10.8%`

## Источники и рецепты

Приоритет (от самого вежливого): (1) **официальная выгрузка** — XLSX/CSV-прайс или
YML-фид (`recipe: price_xlsx` / `feed_xml`): один файл, парсим офлайн; (2) карточки
на сайте — `rest_html` (берёт микроразметку schema.org `itemprop`, листает `?p=`);
(3) если за антиботом — рецепт `stealth_browser` навыка (ставится отдельно, см.
`references/anti_bot.md`). Капча/бан — стоп-сигнал «снизь темп / найди выгрузку /
сними вручную», а не «дожимай».

Подключены и проверены (2026-06-21/22):
- **VALTEC** (`price_xlsx`) — официальный XLSX-прайс, ссылка на свежий .xlsx берётся
  со страницы прайса (`price_page`), дюймы → Ду. 4151 позиция.
- **DUX / Дюкс** (`rest_html`) — счётчики воды, цены из карточек (schema.org). Цена
  «по запросу» (0) пропускается. DN берётся из имени (`dn_regex`).
- **Пульсар** (`rest_html`) — счётчики воды (pulsarm.ru, schema.org). Даёт ВТОРОЙ
  источник в счётчиках → сравнение «где дешевле» между поставщиками работает.

Подключить ЕЩЁ источник (чек-лист этики обязателен):
1. Открой `https://<домен>/robots.txt` — путь к выгрузке не должен быть запрещён
   (модуль проверяет сам и блокирует сбор, если запрещено).
2. Прочитай ToS — нет ли прямого запрета на автоматический сбор.
3. В `config/sources.yaml` пропиши `recipe`+адрес, выставь `robots_checked: true`,
   `tos_ok: true`, `enabled: true`.
4. Сначала пилот на 3–5 позициях, глазами проверь `qa_report.md` и `comparison.xlsx`
   — потом масштабируй.

Разведка robots.txt: `valtec.ru`, `veza.ru`, `teplovodomer.ru` разрешают каталог.

## Межвендорное сопоставление — что важно понимать

Цены у РАЗНЫХ брендов названы по-разному, поэтому точное совпадение варианта редко.
Модуль надёжно опознаёт **тип товара (кран/фильтр/счётчик) + размер (DN)** и показывает:
ближайший вариант, **диапазон цен** по типу+размеру и **точность** (match_score).
Аксессуары/запчасти («…для счётчика», «фильтроэлемент») отбраковываются.

**«Экономию %» заявляем только при уверенном совпадении** (score ≥ 0.6) — иначе это
«похожие варианты, проверить». Точное сопоставление варианта — задача матчинга
бэкенда (правила + LLM); этот модуль ДОСТАВЛЯЕТ внешние цены и кандидатов для проверки.

Практический вывод: источник даёт максимум пользы, когда он держит те же бренды/товары,
что и спецификация. Пример: прайс VALTEC точнее всего ложится на позиции, где спека —
это VALTEC-арматура; на «чужих» брендах (Пульсар, ФММ) выходит диапазон по типу+DN.

## Деление спецификации на группы живёт в ДВУХ местах

`research/klassifikator_pozicij.py` — по нему реально идёт поиск цен.
`backend/src/services/specClassifier.ts` — по нему страница проекта показывает состав
спецификации («что уйдёт в поиск: 175 из 252, из них 54 с заводской маркой»).

Разойдутся — экран будет обещать одно, а искаться будет другое, и заметить это некому.
После правки ЛЮБОГО из двух файлов прогнать сверку, три команды по порядку:

```
python price-harvester/research/sverka_klassifikatora_python.py
cd backend && npx ts-node sverka_klassifikatora_ts.ts
python price-harvester/research/sverka_klassifikatora.py
```

Ожидаемое — «РАСХОЖДЕНИЙ НЕТ — 1:1». Последняя сверка 26.08.2026: 7039 из 7039 строк базы.
Быстрый сторож на 16 характерных случаев, без базы: `cd backend && npx ts-node test_spec_classifier.ts`.

## Идемпотентность

Ключ — БИЗНЕС-ключ `источник | позиция | артикул/имя | единица | дата среза`, не
байты. Повторный прогон в тот же день обновляет строки, а не задваивает; другой
день = новый срез (история цен). При укладке устаревшие строки текущего среза
(пары «позиция × источник») удаляются — исчезнувшие матчи не остаются сиротами.

## Таблица external_prices (создаётся модулем)

Провенанс (`source`, `source_url`, `snapshot_date`) + сопоставимость (`currency`,
`vat_included`, `vat_rate`, `min_batch`, `lead_time_days`, `in_stock`) +
`spec_item_id` (к какой позиции), `match_score`, `status` (found/not_found/blocked),
`raw_data` (сырьё), `business_key` (UNIQUE).

## Что дальше (Фаза 2, опционально, по твоему решению)

Проекция выбранных строк `external_prices` в `price_list_items` под служебный
`price_lists` — тогда существующий матчер увидит внешние цены В ПРИЛОЖЕНИИ без
правок кода (обратимо: удалил служебный прайс — чисто). Включать после того, как
качество внешних цен устроит и работа над качеством матчинга будет спокойной.
